# 집중 환경 체크

PC 앞에서 혼자 공부할 때, 지금 책상이 집중하기 좋은 상태인지와 방해 요인이 소음인지, 온습도인지, 밝기인지 알려 주는 웹 대시보드입니다.
K-Digital 피지컬AI 과정 10/29 수업의 P01 공통 연결(Arduino UNO + Web Serial)을 바탕으로 사운드 센서를 더했고, XIAO ESP32S3 Sense로 같은 판단을 핸드폰에서도 보고 LED를 켜고 끌 수 있게 했습니다.

## 사용자와 판단

| 항목 | 내용 |
|---|---|
| 사용자 | PC 앞에서 혼자 공부하는 나 |
| 상황 | 공부하다 집중이 흐트러지는데, 원인이 소음인지 더위·습기인지 어두운 조명인지 모름 |
| 화면이 돕는 판단 | 지금 집중하기 좋은가? 방해 요인은 무엇인가? 언제 시끄러웠나? |
| 입력 | 사운드 센서 AO(UNO A2), DHT11(UNO D4), 조도 센서 CdS(UNO A1), 버튼(UNO D2) |
| 출력 | PC·핸드폰 화면 판단, LED(UNO D8) 켜기·끄기·깜빡임, LCD(온습도·소음·LED 상태) |

## 주요 기능

- **맨 위 판단 하나**: “집중하기 좋음 / 소음 주의 / 환경 조정 필요 / 소음 때문에 집중하기 어려움”과 그 이유를 색·아이콘 모양·문구로 함께 보여 줍니다.
- **소음·온도·습도·밝기 카드**: 현재값, 기준, 쾌적 범위, 최근 10분 범위
- **내 방에 맞춘 기준**
  - 소음: 조용할 때 10초 측정 → 그 값의 2배부터 주의, 3배부터 시끄러움(배수 선택 가능)
  - 밝기: 평소 공부 조명에서 10초 측정 → 그 값의 60% 아래면 어두움(50·60·70% 선택)
- **최근 10분 그래프**: 소음(위)과 밝기(아래)를 같은 시간 축으로 그리고, 마우스나 좌우 화살표로 고른 시각의 두 값을 함께 보여 줍니다.
- **시끄러웠던 때 기록**: 시끄러움 단계에 들어간 시각을 자동으로 남깁니다.
- **LED**
  - 화면·핸드폰에서 켜기/끄기
  - 보드 버튼을 누를 때마다 켜짐↔꺼짐
  - 시끄러움 단계 동안 1초에 4번 깜빡임(선택). 조용해지면 원래 상태로 돌아가고, 깜빡이는 중에 버튼을 누르면 알림을 끕니다.
- **핸드폰 연동**: XIAO가 핸드폰 핫스팟에 접속해 핸드폰 브라우저에 판단·소음·온습도와 LED 버튼을 보여 줍니다.
- **오류 표시**: 센서값 없음, 데이터 끊김(판단 보류), 사용 중 USB 빠짐(“연결 끊김” + 마지막 수신 시각)을 구분합니다.

## 전체 구조

```
[DHT11·사운드 센서·CdS·버튼·LED·LCD] ─ UNO ──USB──┐
                                                PC 대시보드 (판단)
                        XIAO ESP32S3 Sense ──USB──┘
                                 │
                                 └─ Wi-Fi(핸드폰 핫스팟) ─ 핸드폰 화면
```

- UNO는 센서를 읽고 LED·LCD를 다룹니다.
- PC 대시보드가 판단을 맡고, 1초마다 판단과 값을 XIAO에 보냅니다.
- 핸드폰에서 누른 LED 명령은 XIAO → PC 대시보드 → UNO 순서로 전달됩니다.
- 보드끼리는 선을 잇지 않습니다. UNO(5V)와 XIAO(3.3V)를 직접 이으면 전압 변환과 배선이 더 필요하고, 판단을 PC 한 곳에서만 해야 PC와 핸드폰이 항상 같은 판단을 보여 줍니다.

## 배선

UNO 연결 핀: D2(버튼), D4(DHT11), D8(LED·1kΩ), A1(CdS·10kΩ), A2(사운드 센서 AO), A4·A5(LCD I2C), 5V, GND
수업 P01 회로에서 가변저항(A0)은 쓰지 않아 뺐습니다. XIAO는 배선 없이 USB로만 연결합니다.

| 부품 | 연결 | 비고 |
|---|---|---|
| 사운드 센서 VCC / GND | 빵판의 5V / GND가 흐르는 줄의 빈 구멍 | 같은 줄 A–E는 같은 금속판 |
| 사운드 센서 AO | UNO A2 | DO는 쓰지 않음 |
| CdS | 한쪽 다리 5V, 다른 다리는 10kΩ과 A1이 만나는 줄 | 10kΩ 다른 끝은 GND. 밝을수록 값이 큼 |
| DHT11 | S → D4, 가운데 → 5V, − → GND | 기판 글자로 핀 확인 |
| LED | D8 → 1kΩ → 긴 다리(+), 짧은 다리(−) → GND | 5V에 바로 연결하면 끌 수 없음 |
| 버튼 | 한쪽 D2, 다른 쪽 GND | INPUT_PULLUP |
| LCD1602 I2C | SDA → A4, SCL → A5, VCC → 5V, GND → GND | |

## 실행 방법

**처음 한 번 (업로드)**
1. Arduino IDE에서 `firmware/P01/P01.ino`를 열고 보드 **Arduino Uno**로 업로드합니다. 라이브러리: DHT sensor library, Adafruit Unified Sensor, hd44780.
2. `firmware/xiao_phone/secrets.example.h`를 복사해 `secrets.h`로 이름을 바꾸고 핸드폰 핫스팟 이름과 비밀번호를 넣습니다. Windows에서 확장자가 숨겨져 있으면 `secrets.h.h`로 저장되니 주의합니다.
3. `firmware/xiao_phone/xiao_phone.ino`를 열고 보드 **XIAO_ESP32S3**로 업로드합니다.
4. 사운드 센서 감도 나사(다회전)를 조절합니다. 조용할 때 감지 LED(L2)가 꺼지고, 음악에 맞춰 깜빡이는 위치가 적당합니다.

**사용할 때**
1. 핸드폰 모바일 핫스팟을 켭니다(2.4GHz).
2. Arduino IDE 시리얼 모니터를 모두 닫습니다.
3. 이 폴더에서 `python -m http.server 8765`를 실행하고 Chrome/Edge에서 `http://localhost:8765`를 엽니다.
4. 「UNO USB 연결」 → UNO 포트(예: COM7), 「XIAO 연결」 → XIAO 포트(예: COM9)를 고릅니다.
5. 「조용할 때 10초 측정」과 「지금 밝기로 10초 측정」으로 기준을 정합니다. 기준은 이 브라우저에 저장됩니다.
6. 화면의 “핸드폰 접속 주소”를 핸드폰 Chrome에서 엽니다. XIAO가 다시 켜지면 주소가 바뀔 수 있습니다.

## 통신 약속 (JSON 한 줄)

**UNO → PC (1초마다, 버튼을 누르면 바로)**
`{"v":1,"type":"state","profile":"P01","request":0,"ms":…,"light_raw":…,"button_pressed":…,"led":0|1,"blink":true|false,"auto":…,"lcd_ready":…,"temperature_c":…|null,"humidity_pct":…|null,"sound_pp":…|null}`

**PC → UNO 명령** (`요청번호 명령 인수`, 보드는 같은 요청번호의 ACK 또는 error로 응답)

| 명령 | 동작 |
|---|---|
| `LED 1` / `LED 0` | LED 켜기 / 끄기 (깜빡임도 멈춤) |
| `BLINK 1` / `BLINK 0` | 1초에 4번 깜빡이기 시작 / 멈추고 원래 상태로 |
| `TOGGLE` | LED를 지금과 반대로 |
| `STOP` | 자동·깜빡임 해제, LED 끄기 |
| `STATUS` · `PING` · `AUTO` · `THRESH` | 수업 P01과 같음 |

**PC ↔ XIAO**

| 방향 | 줄 | 내용 |
|---|---|---|
| PC → XIAO | `{"t":"view", …}` | 1초마다 지금 판단과 값 |
| PC → XIAO | `{"t":"result","id","ok","text"}` | 핸드폰 명령의 처리 결과 |
| XIAO → PC | `{"t":"wifi","status","ssid","ip"}` | 3초마다 Wi-Fi 상태와 접속 주소 |
| XIAO → PC | `{"t":"cmd","id","cmd":"LED 1"}` | 핸드폰에서 누른 명령 (`LED 1`, `LED 0`만 허용) |

모든 명령은 수업 P01 규칙을 따릅니다. 요청번호를 붙여 보내고, 같은 번호의 ACK가 와야 적용으로 표시하며, 응답이 없으면 “적용 여부 미확인”으로 표시하고 자동으로 다시 보내지 않습니다.

## 설계 이유

- **기준을 측정으로 정함**: 사운드 센서 값은 dB가 아니고, CdS 값은 lux가 아니며, 둘 다 방과 센서 위치마다 다릅니다. 그래서 고정값 대신 내 방에서 10초 측정한 중앙값을 기준으로 삼고, 배수·비율은 사용자가 고릅니다.
- **깜빡임 방지**: 최근 3초 평균으로 판단하고, 단계에서 벗어날 때는 기준보다 10% 더 넘어가야 바뀝니다.
- **판단 순서**: 소음이 시끄러우면 그것을 먼저 보여 주고, 그다음 온도·습도·어두움이 범위를 벗어나면 “환경 조정 필요”와 함께 이유를 모두 적습니다.
- **그래프를 두 개로 나눔**: 소음(0–60쯤)과 밝기(0–1023)는 단위가 달라 한 그래프에 세로축 두 개로 겹치면, 선이 만나는 지점에 의미가 없는데도 관계가 있어 보입니다. 같은 시간 축을 공유하는 두 그래프로 그렸습니다. 선 색(소음 #B04A28, 밝기 #3A6EA5)은 색각 이상 시뮬레이션을 포함한 구분·대비 검사를 통과했고, 선 끝 이름표로 색만으로 구분하지 않게 했습니다.
- **깜빡임은 보드가 직접**: 화면이 0.125초마다 명령을 보내지 않고 `BLINK 1` 한 번만 보내면 보드가 직접 깜빡입니다. `TOGGLE`도 보드가 직접 뒤집어, 버튼과 동시에 써도 상태가 어긋나지 않습니다.
- **버튼 채터링 방지**: 30ms 동안 안정된 눌림만 한 번으로 셉니다.
- **디자인**: [open-design](https://github.com/nexu-io/open-design)(Apache-2.0)의 warm-editorial 디자인 시스템을 바탕으로, 따뜻한 종이색 바탕·세리프 숫자·테라코타 강조 한 가지로 PC와 핸드폰 화면을 맞췄습니다. 원본 테라코타(#C0512F)는 버튼 글자 대비가 4.5:1에 못 미쳐 #B04A28로 진하게 썼습니다.

|---|---|

| 시리얼로 보드 명령 시험 | `TOGGLE`, `BLINK 1/0`, `LED`, `STOP`의 응답과 LED 상태 확인, 잘못된 형식은 거절 |
| 연습 데이터로 PC 화면 | 소음·밝기 기준 측정, 단계 전환, 시끄러운 시각 기록, 깜빡임 명령·ACK, 센서 null, 두 그래프와 말풍선 |
| 실제 장치 | 아래 체크리스트 |

- [x] 화면에 소음 상대값이 1초마다 바뀌고, 음악 소리에 올라간다
- [x] 기준 측정 후 소리에 따라 “소음 주의”, “소음 때문에 집중하기 어려움”으로 바뀐다

- [x] 시끄러움 단계가 되면 실제 LED가 깜빡인다 (LCD `LED:B`)
- [x] USB를 뽑으면 “연결 끊김”과 마지막 정상 수신 시각이 표시된다
- [x] 핸드폰에서 판단·소음·온습도가 PC와 같게 표시되고, LED 켜기/끄기가 동작한다
- [x] PC 대시보드를 닫으면 핸드폰이 곧바로 “판단 보류”로 바뀐다

| 화면 코드를 고쳐도 시끄러울 때 LED가 깜빡이지 않고 켜지기만 함 | 브라우저가 예전 `dashboard.js`를 기억하고 있었음(보드는 정상) | HTML에서 CSS·JS 주소에 버전 표시를 붙여 새로고침만 해도 최신 파일을 받게 함 |
| 화면 검사 코드에 단 주석이 같은 줄의 LED 값 검사까지 덮음 | 주석 위치 실수 | 주석을 윗줄로 옮겨 LED 값 검사를 되살림 |

## 보안과 한계

- 핸드폰 화면에는 로그인이 없습니다. 같은 핫스팟에 접속한 기기는 LED를 켜고 끌 수 있으므로 핫스팟 비밀번호를 공유하지 않습니다.
- 측정값은 PC, XIAO, 핸드폰 사이에서만 오가며 인터넷 서버로 보내지 않습니다. 화면 글꼴만 인터넷(Google Fonts)에서 불러오고, 연결이 없으면 기본 글꼴로 표시합니다.
- PC 대시보드를 닫거나 새로고침하면 그래프와 시끄러웠던 때 기록이 지워집니다.
- 깜빡이는 중에 USB를 뽑으면 보드는 화면이 닫힌 것을 알 수 없어 계속 깜빡입니다. 버튼을 누르면 멈춥니다.
- 핸드폰 화면에는 밝기 카드가 따로 없고, 판단 이유에 “어두움”이 표시됩니다.
